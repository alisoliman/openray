# OpenRay usability review — 8–12 September 2026

The main journey is now defined as **select text → open a writing command → refine → accept into the original app**. Hiding the launcher is a pause; Back is navigation. These distinctions remove the manual copy/paste loop without allowing a resumed result to replace text in an unrelated app.

This is a broad expert review of the native macOS application, with source and test inspection followed by implementation verification. It is **not a recruited participant study**: no participant sample, success-rate measurement, interview findings, or statistical claims are implied. The initial source baseline was `05dac2112cdefd3d00eca71f5f364e73e889b18f`. The earlier [September 5 review](../UI-UX-REVIEW.md) is historical evidence, not proof that its live checks were rerun for this change.

## Method and evidence

The review followed the user's task from entry to outcome, then examined interruptions, keyboard-only use, error recovery, creation flows, search narrowing, permissions, and long-lived utilities. Findings below identify behavior directly visible in source rather than inferring user reactions from screenshots.

- **Source reviewed:** control flow and current automated-test assertions were inspected. This establishes an implementation finding, not a live usability measurement.
- **Automated verified:** reserved for tests actually executed for this change, recorded in the verification section.
- **Live verified:** reserved for interactions actually observed in the exact build under review, recorded separately with their limitations.
- **Further observation:** a plausible concern that needs hands-on or participant evidence before treating it as a defect.

Primary files: `LauncherModel.swift`, `LauncherPanelController.swift`, `ContentView.swift`, `LauncherSearchView.swift`, `FileSearchService.swift`, `SelectedTextContext.swift`, `NativeInputs.swift`, `AIChatView.swift`, `AIChatModel.swift`, `AIModels.swift`, `FoundationModelEngine.swift`, `LibraryEditorView.swift`, `SettingsView.swift`, `CaffeinateView.swift`, `PomodoroView.swift`, `NativeActionsMenu.swift`, and the corresponding test suites.

## Prioritized findings and acceptance criteria

| ID | Priority | Initial behavior and user cost | Required outcome |
| --- | --- | --- | --- |
| UX-01 | P1 | Improve Writing opened an empty composer. Selected text required a separate import, and completed output exposed Copy/Save as Note only. The user had to reconstruct the cross-app task manually. | Capture the invocation's selected-text context. An explicit writing command uses it in an empty tool or starts a new selection after a completed response with no unsent draft/error. Drafts, generation, and failed/stopped states are preserved. Present the destination and offer Return to accept a completed result. |
| UX-02 | P1 | `previousApplication` changed whenever another app became active. A user resuming an older writing task could accidentally target their latest app instead of the source. | Pin source app, focused element, selection range, and text to the writing task. Revalidate before replacement. On mismatch, keep the result and offer recovery; do not guess a new target. |
| UX-03 | P1 | Writing engines reset after every response and wrapped each subsequent message as a new passage. “Make it warmer” was treated as text to rewrite, despite looking like a conversation. | Distinguish source text from follow-up instructions. Refine the current result while preserving the original task; new-source import is explicit. |
| UX-04 | P1 | Return inserted a newline and Command-Return sent, opposite to the requested default. Action buttons and documentation reinforced that convention. | Return submits a nonempty draft. Command-Return inserts a newline. An empty composer may accept only the latest complete writing result; held Return, generation, failure, and partial output must not trigger accidental replacement. |
| UX-05 | P1 | Escape traversed feature → home → cleared query → hidden panel. Users who dismissed with Escape lost their location even though Option-Space already retained it. The generic menu-bar opener also reset to All. | Escape hides; explicit Back/Command-[ navigates. Reopening with either Option-Space or Open OpenRay within five minutes retains destination, query, and selection. Expiry returns to All while preserving AI work and unsaved library editors. |
| UX-06 | P2 | Most feature/destination navigation discarded the search and selection. Only the special Tab-to-AI route remembered an origin. Clicking the current search scope also reset its query, and More scopes still reset after visible scopes were fixed. Older scope history could take precedence over Tab-to-AI's immediate origin. | Back restores the immediate originating workspace and its query/selection. Opening Settings from AI returns to AI. Every scope, including More choices, preserves query; selecting the current scope is a no-op. Tab-to-AI participates in the same navigation history. |
| UX-07 | P2 | Composer Tab/Shift-Tab changed AI tools, intercepting ordinary keyboard focus traversal. Native traversal alone also left SwiftUI buttons outside the focus loop when macOS button navigation was off. | Restore traversal and give the actual AI buttons explicit keyboard focus and Return/Space activation. Keep tool buttons and Command-1…6 for deliberate tool switching. |
| UX-08 | P2 | Importing selected text or clipboard content replaced the unsent draft, while visible conversation and underlying model context could refer to the old source. | Validate new source before changing state, disable import while generating, and make its new-source meaning clear. Automatic selection import must preserve existing work. |
| UX-09 | P2 | A failed or stopped request consumed the draft and left the source only in the transcript, with no convenient retry/edit path. A follow-up already typed during a failed first response could then be mistaken for a new passage. | Restore the failed request only if no newer draft exists. Preserve the original passage when sending an already-typed follow-up. Retry keeps its original context; Use Last Result starts fresh model context from the latest completed result while preserving its source target. Partial or older responses must never be accepted by default after failure. |
| UX-10 | P2 | Settings exclusions lived in view-local state initialized on appearance. Navigating away could discard an unsaved change with no recovery. | Retain the exclusion draft across navigation or provide a clear save/discard decision. Hiding must preserve it. |
| UX-11 | P2 | `openAI` ignored failure from activating a different tool during generation; it could navigate into the still-active tool under the requested command's intent. | Refused tool changes preserve both task and navigation and show the reason. |
| UX-12 | P2 | Help, README, and privacy text described the old keys and stated selected text entered AI only through import buttons. | Document exact trigger, target, follow-up, pause/resume, and new-source behavior consistently with the implementation. |
| UX-13 | P1 | The user reported the caret and placeholder appearing at different positions or overlapping in the AI composer. Placeholder text was a separate SwiftUI overlay around a native text view. | Draw the placeholder inside the native text view using its text-container origin and font, and use the same baseline for text and insertion point. Native observation must confirm alignment, beyond a geometry assertion. |
| UX-14 | P2 | Hiding stopped Spotlight; reopening cleared its result list before the asynchronous same-query refresh. The selected file could fall back to the first result before the previous matches returned. Back across All/Files could similarly discard a restored ID during the required new query. | Retain the bounded result snapshot only for the same trimmed query and recent-files mode. Hold a restored file ID until its refresh completes; Enter must not execute a fallback result while restoration is pending. Replace with fresh results, clear for a different query/mode, and reconcile removals normally. |
| UX-15 | P2 | Captured source targets needed a defined lifetime. Starting new conversations could retain obsolete source contexts; after a successful insertion the original selected range no longer described the inserted result. | New Conversation and new-source imports remove obsolete contexts. Successful insertion retires the target and gives reselect guidance; later refinements remain copyable until the inserted text is selected again. Validate source identity and current foreground/clipboard state immediately before insertion. |
| UX-16 | P1 | Carbon hotkeys were registered without exclusivity. Multiple OpenRay instances could receive Option-Space and race to activate, making invocation and selection capture ambiguous even when registration succeeded. | Register global shortcuts exclusively so conflicts are reported instead of activating multiple instances. The updated source passed targeted tests and is included in the September 12 signed review build. Native OpenRay Settings confirmed Accessibility enabled for that exact build on September 12; successful shortcut delivery and replacement require separate live evidence. |
| UX-17 | P2 | Caffeinate kept pending duration controls in view-local state. Native verification reproduced Custom → 90 minutes → Back → reopen resetting to Indefinitely without starting the timer. | Keep the pending controls in launcher memory across navigation and hiding. Untouched controls follow changes to the active timer; edited controls survive those changes until explicitly submitted. Navigation and draft restoration never start Caffeinate. |

The listed outcomes are implemented in the reviewed source. Completion of an acceptance check still requires the evidence recorded below; implementation alone does not certify real cross-app Accessibility behavior. Additional integration fixes preserve AI-tool identity through Back navigation, apply expiry before explicit menu/hotkey destinations, keep identical-text selections in different fields distinct, and preserve Ask history when importing selected text.

## Further observation

These are bounded coverage gaps, not asserted defects or claims about users:

- **New conversation recovery:** Command-N intentionally starts fresh, but recovery of a mistaken new conversation could help. Decide after observing real accidental-loss frequency; do not silently persist conversations to disk to implement undo.
- **Mouse preview expectations:** result rows execute on one click. Observe whether users trying to preview clipboard or note contents expect selection without execution before changing the app-wide click convention.
- **Visual and assistive use:** inspect long text, larger display scaling, high contrast, reduced motion, and an actual VoiceOver session. Explicit AI button focus is implemented; its end-to-end traversal result must be recorded separately below. Source accessibility labels alone do not establish a full accessibility audit.
- **App compatibility:** source-range validation and replacement depend on the source application's Accessibility implementation. Native text fields, browser editors, rich text, secure text, and app termination each need explicit evidence; one successful editor does not certify all apps.
